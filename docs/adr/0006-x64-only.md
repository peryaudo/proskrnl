# ADR 0006 — x86-64 only; 32-bit via WOW64, added last

**Status:** Accepted

## Context
x86-32 carries a dirtier ABI than x64: stack-chained `fs:[0]` SEH frames and the
`__cdecl/__stdcall/__fastcall/__thiscall` calling-convention zoo. x64 is where Microsoft
burned that debt once — table-based SEH, one calling convention. Modern Wine's centre of
gravity is x64, and its "new WoW64" runs 32-bit PE ntdll over a 64-bit unixlib with no
32-bit unix code.

## Decision
Target x86-64 only. Support 32-bit apps via WOW64, added as the final, purely-additive step.

## Consequences
- `ps/usermode.c` exception delivery is simpler (table-based unwind vs. chained frames).
- 32-bit apps still run; the 32→64 transition is entirely user-mode (Wine's new WoW64), so
  the kernel never sees a 32-bit syscall and pays only a few hundred lines (GDT compat
  descriptors, an `IMAGE_FILE_MACHINE_I386` branch, low-4GB restriction, compat-mode
  exception delivery, `ProcessWow64Information`).
- WOW64 touches no `Nt*` semantics and is removable; calc.exe is 64-bit, so WOW64 goes last.
- Gives up Wine's most-mature 32-bit-native path. Accepted for the cleaner ABI and better
  teaching value.
