# The winetest gate's manifest (tests/run/run.sh winetest): the FULL non-GUI
# sweep of Wine's own test suite — every subtest of ntdll, kernel32,
# programs/cmd, msvcrt and ucrtbase, run under the pinned Wine oracle AND on
# proskrnl from ONE binary per module (Makefile `wtests`, the pinned tree's
# own unmodified test objects linked standalone).
#
# Syntax: `<exe>:<subtest>[:<budget>][:<timeout_s>]`, one per line — the same
# grammar manifest-gui.txt uses, and the same one both readers parse
# (tests/run/run.sh wtest_parse_manifest, and user/smss/session.c
# SessionParseWtestManifest, which is what the kernel-side sweep reads off the
# baked image). A line whose first character is '#' is a COMMENT, and so are
# blank lines. Comments are whole-line only: there is no trailing-# form,
# because a '#' is a legal character in no field and adding one would make a
# typo'd pair name parse as a shorter pair rather than fail loudly.
#
#   budget       the accepted failure COUNT for this pair on proskrnl —
#                winetest's exit status is its failure count, and the leg
#                fails on anything above this. Default 0, which is what every
#                pair in THIS file carries: a CUI pair is activated green or
#                it stays parked (the "never activate a red pair" rule below).
#                A budget is for a pair whose remaining failures are named,
#                understood and ratcheted down one commit at a time — today
#                that is user32:msg alone, in manifest-gui.txt. It only ever
#                DECREASES, in the same commit as the fix that earns it (G13).
#                The ORACLE half is not budgeted on either leg: it is the spec
#                side, and a pair red there convicts nothing (Art. 6).
#   timeout_s    the per-pair timeout in seconds, default 300.
#
# Both optional fields are POSITIONAL, so a pair that wants only a timeout
# writes the budget out: `mmdevapi_test.exe:render:0:600`. An empty field is
# legal and means the default, but nothing here spells it that way — `pair::600`
# and `pair:600` differ by one character and mean opposite things, and the
# second used to BE the timeout syntax.
#
# advapi32 is deliberately out: its subject is the security/registry service
# surface, covered by the CUI-2/CUI-3 legs (tests/run/run.sh console, scm) and
# by tests/ntapi, not by this gate. user32 is out too — the GUI trophy has its
# own manifest (manifest-gui.txt, tests/run/run.sh winetest-gui).
#
# COVERAGE IS THE COMMENTS, THE GATE IS THE ACTIVE LIST. This file lists
# every pair the five modules have; the ACTIVE (uncommented) lines are the
# ones the gate runs and must keep green, and every pair that is not green
# today is commented out with its triage written above it. Nothing is
# deleted — a commented-out pair is a worked frontier entry, not a dropped
# one, and its block says how many assertions still fail and why.
#
# ---------------------------------------------------------------------------
# WHY A PAIR IS COMMENTED OUT
#
# Two different reasons, and each block below says which it is.
#
#   1. RED AND FIXABLE. The pair fails on proskrnl for a reason that is a
#      kernel gap, the block names the cause and the current failure count,
#      and it ends with `# TODO: Implement`. It is commented out so the gate
#      stays a pass/fail signal rather than a permanently-red wall; the
#      TODO is the work item, and the counts are the yardstick for the next
#      person to check progress against.
#
#   2. NOT REACHABLE UNDER THE SCOPE. The pair cannot go green without
#      changing something the project has decided not to change, so it
#      carries NO TODO. These blocks name the deciding constraint (the FAT32
#      backend, the CUI/GUI split, a constitution article) so the exclusion
#      can be re-argued if the constraint ever moves.
#
# The older, narrower categories below still apply and still name their
# measurement — they are the subset of (2) that predates this sweep:
#
#   (a) proskrnl will never implement the surface, by a decision already
#       recorded elsewhere (docs/03, an ADR). The pair cannot go green
#       without reversing that decision, so leaving it in would make the
#       gate permanently red on purpose.
#
#   (b) the ORACLE cannot serve as the spec for it — it fails or dies on the
#       pinned Wine itself, or it asserts something about the standalone
#       link rather than about the boundary. A pair that is red with zero
#       proskrnl involvement cannot convict the kernel (Art. 6), so it
#       cannot sit in a differential gate.
#
#   (c) the pair's subject needs a GUI BOOT — see THE PLACEMENT RULE below,
#       which is what decides the file rather than this category deciding it.
#       A (c) pair is simply one the rule sends to manifest-gui.txt: the
#       exclusion must still name the specific dependency, and a pair whose
#       GUI blocker is only one of several is still a (c) pair.
#
# ---------------------------------------------------------------------------
# THE PLACEMENT RULE — which manifest a pair belongs in
#
#   A pair that CAN pass on this leg's machines belongs HERE.
#   A pair that CANNOT belongs in manifest-gui.txt.
#
# That is the whole rule, and it is about the MACHINE, not about why the pair
# is red today. "This leg's machines" are the two boots run.sh winetest gives
# a pair: the Gui=0 CUI boot, and — for the audio modules only — the Gui=1
# virtio-snd boot the same leg provides (the AUD-2 amendment below). If
# passing needs anything else a desktop supplies — a window, a window station,
# a DLL whose imports pull in user32/gdi32 — no amount of kernel work makes
# the pair green on this leg, and it goes in the GUI list whether it is active
# or parked.
#
# Corollaries, each of which has caught a real miscall:
#
#   - A GUI-dependent pair moves EVEN IF it also has non-GUI blockers. Where
#     it can eventually pass is what places it; what else is wrong with it is
#     triage, and triage travels with the pair. ws2_32:sock and ws2_32:protocol
#     were kept here on the opposite reasoning — "moving it would say the
#     desktop is all it waits for" — and that was wrong: neither can pass on a
#     Gui=0 boot at all (protocol's WSAAsyncGetXByY block needs a WINDOW and
#     spins forever without one), so this file was claiming coverage of two
#     pairs it can never turn green. Both are in manifest-gui.txt now, with
#     their AF_INET6 and live-DNS blockers written down beside the GUI one.
#   - A pair that is merely RED here stays here. Kernel gaps, FAT-floor
#     limits, oracle flakes — none of those is a machine question.
#   - Placement is not a judgement about difficulty. ntdll:om, ntdll:rtl and
#     kernel32:toolhelp moved for this rule, not because they looked hard.
#
# tools/check_wtest_manifests.py enforces what is mechanical about this — a
# user32 pair is never in this file, and every pair is declared exactly once —
# but WHICH file a CUI module's pair belongs in is this rule applied by
# whoever writes the triage. Say which half of the rule you applied.
#
#       AUD-2 AMENDMENT (docs/23 §6c): the AUDIO modules (mmdevapi_test.exe,
#       winmm_test.exe) are why the rule says "this leg's machineS", plural.
#       Their pairs live in THIS manifest — the audio milestones' done-when
#       counts against it — and the runner partitions them onto their own
#       BOOT (run.sh wtest_is_audio): a Gui=1 boot with the virtio-snd device
#       on the QEMU command line, against the CUI arm's Gui=0 one. They pass
#       on a machine THIS leg provides, so the rule keeps them here. Both arms
#       boot copies of the same image; only the flags and the devices differ,
#       and a pair from any other module never joins the audio arm.
# ---------------------------------------------------------------------------
#
# Every oracle-side measurement below was taken as an ORDINARY USER under a
# UTF-8 locale, which the runner now enforces (tests/run/run.sh): before that
# it ran as root under C/POSIX, and eight pairs looked oracle-red that were
# not — ntdll:directory (82 failures), ntdll:file (6), ntdll:change (1),
# kernel32:profile (4), kernel32:version (36), kernel32:comm (3),
# kernel32:file (7) and ucrtbase:file (a crash) are all 0-failure green once
# the host stopped leaking into the answer. docs/03 "M10 winetest notes" has
# the whole story; do not re-park a pair on an oracle failure without
# re-measuring it that way first.
#
# ONE OF THOSE EIGHT GOES RED ON SOME DEVELOPER HOSTS, AND IT IS NOT THE
# KERNEL — kernel32:version, now PARKED for that reason (its block below has
# the full signature and the trade). It fails the ORACLE leg on at least one
# KVM developer box with exactly the 36 failures the root/C-POSIX era
# produced, while proskrnl's half passes and CI is green on both legs.
#
# It used to stay ACTIVE on the strength of being green on CI. That was the
# wrong trade: it made `make fulltest` permanently red on a developer box,
# and a suite that is always red is a suite people stop reading — the same
# argument this header makes two paragraphs up for never activating a red
# pair. Coverage lost to a parked pair is visible in this file; attention
# lost to a red gate is not.
#
# The lesson for the NEXT host-local residue: park it, write the signature
# down, and say what would un-park it. Do not leave the gate red and expect
# everyone to remember why.
# ---------------------------------------------------------------------------
