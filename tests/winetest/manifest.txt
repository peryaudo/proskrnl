# The winetest gate's manifest (tests/run/run.sh winetest): the FULL non-GUI
# sweep of Wine's own test suite — every subtest of ntdll, kernel32,
# programs/cmd, msvcrt and ucrtbase, run under the pinned Wine oracle AND on
# proskrnl from ONE binary per module (Makefile `wtests`, the pinned tree's
# own unmodified test objects linked standalone).
#
# Syntax: `<exe>:<subtest>[:<timeout_s>]`, one per line. A line whose first
# character is '#' is a COMMENT, and so are blank lines — both readers agree
# (tests/run/run.sh winetest, and user/smss/session.c
# SessionParseWtestManifest, which is what the kernel-side sweep parses off
# the baked image). Comments are whole-line only: there is no trailing-#
# form, because a '#' is a legal character in neither field and adding one
# would make a typo'd pair name parse as a shorter pair rather than fail
# loudly. The optional third field is the per-pair timeout in seconds
# (default 300).
#
# advapi32 is deliberately out: its subject is the security/registry service
# surface, covered by the CUI-2/CUI-3 legs (tests/run/run.sh console, scm) and
# by tests/ntapi, not by this gate. user32 is out too — the GUI trophy has its
# own manifest (manifest-gui.txt, tests/run/run.sh guiwtest).
#
# COVERAGE IS THE COMMENTS, THE GATE IS THE ACTIVE LIST. This file lists
# every pair the five modules have; the ACTIVE (uncommented) lines are the
# ones the gate runs and must keep green, and every pair that is not green
# today is commented out with its triage written above it. Nothing is
# deleted — a commented-out pair is a worked frontier entry, not a dropped
# one, and its block says how many assertions still fail and why.
#
# ---------------------------------------------------------------------------
# WHY A PAIR IS COMMENTED OUT
#
# Two different reasons, and each block below says which it is.
#
#   1. RED AND FIXABLE. The pair fails on proskrnl for a reason that is a
#      kernel gap, the block names the cause and the current failure count,
#      and it ends with `# TODO: Implement`. It is commented out so the gate
#      stays a pass/fail signal rather than a permanently-red wall; the
#      TODO is the work item, and the counts are the yardstick for the next
#      person to check progress against.
#
#   2. NOT REACHABLE UNDER THE SCOPE. The pair cannot go green without
#      changing something the project has decided not to change, so it
#      carries NO TODO. These blocks name the deciding constraint (the FAT32
#      backend, the CUI/GUI split, a constitution article) so the exclusion
#      can be re-argued if the constraint ever moves.
#
# The older, narrower categories below still apply and still name their
# measurement — they are the subset of (2) that predates this sweep:
#
#   (a) proskrnl will never implement the surface, by a decision already
#       recorded elsewhere (docs/03, an ADR). The pair cannot go green
#       without reversing that decision, so leaving it in would make the
#       gate permanently red on purpose.
#
#   (b) the ORACLE cannot serve as the spec for it — it fails or dies on the
#       pinned Wine itself, or it asserts something about the standalone
#       link rather than about the boundary. A pair that is red with zero
#       proskrnl involvement cannot convict the kernel (Art. 6), so it
#       cannot sit in a differential gate.
#
#   (c) the pair's subject is only reachable on the GUI image — it needs a
#       DLL whose imports pull in user32/gdi32, so running it here would
#       mean putting the GUI stack on the CUI volume (G7). This is the same
#       reason user32 is out of this file; such a pair belongs in
#       manifest-gui.txt when that image can carry it, not here. The
#       exclusion must name the specific dependency and show that the
#       failures downstream of it convict nothing — a pair that ALSO fails
#       for a kernel reason stays in and stays red.
#
# Every oracle-side measurement below was taken as an ORDINARY USER under a
# UTF-8 locale, which the runner now enforces (tests/run/run.sh): before that
# it ran as root under C/POSIX, and eight pairs looked oracle-red that were
# not — ntdll:directory (82 failures), ntdll:file (6), ntdll:change (1),
# kernel32:profile (4), kernel32:version (36), kernel32:comm (3),
# kernel32:file (7) and ucrtbase:file (a crash) are all 0-failure green once
# the host stopped leaking into the answer. docs/03 "M10 winetest notes" has
# the whole story; do not re-park a pair on an oracle failure without
# re-measuring it that way first.
# ---------------------------------------------------------------------------
