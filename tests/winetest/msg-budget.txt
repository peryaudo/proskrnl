# The guiwtest ratchet (tests/run/run.sh guiwtest): the currently-accepted
# user32:msg failure count on proskrnl. Only ever DECREASE this number, in
# the same commit as the fix that earned it (G13); the leg fails on any
# count above it, and on any CRASH exit regardless of the number.
#
# The 9999 sentinel is retired: the whole module runs to its own verdict
# (winetest's failure count arrives as the NT exit status). The named
# divergences behind the current number are listed in docs/03 "GUI-5
# winetest notes"; 0 is the end state, and build/tests/guiwtest-msg.log
# names whichever are left after any run (tools/unscreen.py replays them
# out of the console screen diff).
#
#   23  first honest measurement (the module runs end to end)
#   20  the process idle event is a GUI-process thing
#   18  the forced desktop window no longer re-homes the process
#
# The number is a CEILING, not the measured count, and deliberately so:
# the count has two parts.
#
#   STABLE: two waiting on GUI-6 (the desktop window has no owning
#   thread), five in test_WM_COPYDATA (a child process must create its
#   window inside the test's own one-second FindWindow poll, and a process
#   start on this stack costs more than that under TCG - they fail as a
#   block, so they cost no headroom), and two todo_wine tags that are stale
#   here because proskrnl passes what Wine fails (winetest counts a success
#   inside a todo block as a failure, so being RIGHT costs two).
#
#   VOLATILE, 0..7: test_PeekMessage3 sets a 100 ms timer, never kills it,
#   and then asserts seven times that the queue is empty - true where the
#   intervening block runs in microseconds, false where 100 ms of guest
#   time passes first (Wine's own restart_timer makes a late timer due
#   immediately). Measured runs have put 1 and 4 of the seven on the
#   failing side with nothing else changed.
#
# The budget is the stable part plus the volatile family's worst case, so a
# run above it is a real regression rather than a slower runner. It also
# means the ratchet moves only when a STABLE failure is fixed: a run
# measuring 12 rather than 15 has not earned a lower budget, it just got
# lucky with the timer. Ratchet from the stable part, never from the
# measurement.
18
